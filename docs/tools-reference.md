# MCP Task Manager Server — Tool Reference

This document describes the tools exposed by the MCP Task Manager Server, including their purpose, input parameters, return values, validation rules, and error behaviour.

The server currently exposes three tools:

| Tool | Description |
|---|---|
| `create_task` | Creates a new task. |
| `list_tasks` | Retrieves all stored tasks. |
| `complete_task` | Marks an existing task as completed. |

All three tools are registered with the MCP server and can be discovered and invoked by compatible MCP clients.

## 1. Task Data Structure

Each task is represented by a Python dataclass with four fields.

| Field | Type | Description |
|---|---|---|
| `id` | Integer | Unique sequential identifier assigned to the task. |
| `title` | String | Task description supplied during creation. |
| `completed` | Boolean | Indicates whether the task has been completed. |
| `created_at` | String | Task creation timestamp in ISO 8601 format, using UTC. |

### Example task object

```json
{
  "id": 1,
  "title": "Read MCP documentation",
  "completed": false,
  "created_at": "2026-11-14T18:30:00+00:00"
}
```

The timestamp above is illustrative. Actual timestamps are generated when tasks are created.

---

## 2. `create_task`

Creates a new task using a supplied title.

### Input parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `title` | String | Yes | The title or description of the task. |

### Validation

The function checks whether the supplied title contains any non-whitespace characters.

- An empty string is rejected.
- A whitespace-only string is rejected.
- Leading and trailing whitespace is removed before the task is stored.

If validation fails, the function raises a `ValueError` with the message:

```text
Task title cannot be empty.
```

### Example input

```json
{
  "title": "Read MCP documentation"
}
```

### Example successful return value

```json
{
  "success": true,
  "message": "Task created successfully.",
  "task": {
    "id": 1,
    "title": "Read MCP documentation",
    "completed": false,
    "created_at": "2026-11-14T18:30:00+00:00"
  }
}
```

The ID and timestamp are generated by the server. The example values are illustrative.

### Behaviour

When a valid title is supplied, the server:

1. Validates the title.
2. Removes leading and trailing whitespace.
3. Generates the next sequential task ID.
4. Generates a UTC creation timestamp.
5. Creates a task with `completed` set to `false`.
6. Adds the task to the in-memory task list.
7. Returns the created task and a success message.

---

## 3. `list_tasks`

Retrieves all tasks currently stored by the server.

### Input parameters

This tool does not require any input parameters.

### Example invocation

```json
{}
```

### Example successful return value

```json
[
  {
    "id": 1,
    "title": "Read MCP documentation",
    "completed": false,
    "created_at": "2026-11-14T18:30:00+00:00"
  },
  {
    "id": 2,
    "title": "Write project documentation",
    "completed": true,
    "created_at": "2026-11-14T18:35:00+00:00"
  }
]
```

The example contains two illustrative tasks.

### Empty task list

If no tasks have been created, the function returns an empty list:

```json
[]
```

### Behaviour

The function iterates through the in-memory task list and converts each task dataclass into a dictionary using Python's `asdict()` function.

The returned list reflects the tasks currently held by the server process.

---

## 4. `complete_task`

Marks an existing task as completed using its ID.

### Input parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `task_id` | Integer | Yes | The ID of the task to mark as completed. |

### Example input

```json
{
  "task_id": 1
}
```

### Example successful return value

```json
{
  "success": true,
  "message": "Task completed successfully.",
  "task": {
    "id": 1,
    "title": "Read MCP documentation",
    "completed": true,
    "created_at": "2026-11-14T18:30:00+00:00"
  }
}
```

### Behaviour

When a task ID is supplied, the function:

1. Searches the task list for a matching ID.
2. Checks whether the task has already been completed.
3. If it is not completed, updates its `completed` field to `true`.
4. Returns the updated task and a success message.

### Completing an already completed task

The function handles repeated completion requests without raising an error.

Instead, it returns:

```json
{
  "success": true,
  "message": "Task is already completed.",
  "task": {
    "id": 1,
    "title": "Read MCP documentation",
    "completed": true,
    "created_at": "2026-11-14T18:30:00+00:00"
  }
}
```

The task remains completed, and its existing data is returned.

### Handling an unknown task ID

If the supplied ID does not match any task, the function raises a `ValueError`.

Example error message:

```text
Task with ID 99 was not found.
```

The function does not create or modify a task when this happens.

---

## 5. Error Handling Summary

The current implementation uses Python's `ValueError` exception for the two validation and lookup failures.

| Tool | Condition | Behaviour |
|---|---|---|
| `create_task` | Empty or whitespace-only title | Raises `ValueError`. |
| `list_tasks` | No tasks exist | Returns an empty list. |
| `complete_task` | Task already completed | Returns a successful response with an explanatory message. |
| `complete_task` | Task ID does not exist | Raises `ValueError`. |

These describe the Python functions' behaviour. The MCP client or development interface may present tool errors using its own error display.

---

## 6. Storage and State Management

The current server uses an in-memory Python list:

```python
tasks: list[Task] = []
```

Tasks exist only for the lifetime of the running server process.

Consequently:

- Task data is not persisted to disk.
- Restarting the server clears all tasks.
- Task IDs are generated sequentially from 1 when the server starts.
- The implementation does not currently use a database.

This is important when interpreting the results of tool calls: a task created in one running server session should not be assumed to exist after that server has restarted.

## 7. Example Tool Interaction

The following sequence demonstrates how the tools can be used together.

**Step 1: Create a task**

```json
{
  "title": "Build an MCP task manager"
}
```

The server creates the task and returns its generated ID.

**Step 2: Retrieve the task list**

Invoke `list_tasks` with no arguments.

The server returns the newly created task.

**Step 3: Complete the task**

Use the returned task ID as the `task_id` argument to `complete_task`.

**Step 4: Retrieve the task list again**

Invoke `list_tasks` once more.

The task should now have:

```json
{
  "completed": true
}
```

This sequence demonstrates how an MCP client can use the exposed tools to perform a basic task-management workflow.
